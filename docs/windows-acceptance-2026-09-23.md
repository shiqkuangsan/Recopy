# Windows 验收清单

状态：可复用验收清单，勾选框不是历史测试结果。2026-09-23～24 本轮结果与证据来源见 [Windows 验收报告](windows-acceptance-results-2026-09-24.md)。用于本次性能与可靠性优化的发版前验收；macOS 测试通过不能代替本清单。

## 准备

- [ ] 记录 Windows 版本、CPU/内存、显示缩放比例，以及 `git rev-parse HEAD`。确认使用本次推送后的 main，而不是已安装的旧版 1.8.0（本轮未修改版本号）。
- [ ] 完全退出旧 Recopy（包括托盘进程），备份 `%APPDATA%\com.recopy.app` 整个目录，包括数据库和 images。确认进程退出后再复制，保留仍存在的 WAL/SHM 文件。
- [ ] 在 Windows 源码目录运行 `pnpm install --frozen-lockfile`、`pnpm tauri build --no-bundle`，测试 `src-tauri\target\release\recopy.exe`。需已有 Rust/MSVC/WebView2/Tauri 构建环境。普通 CI 仅 cargo check，不提供安装包。
- [ ] 如需验证安装升级，再运行 `pnpm tauri build --bundles nsis`，使用 `src-tauri\target\release\bundle\nsis` 下安装包。构建/安装失败保留完整日志。
- [ ] 准备普通文本、中文、链接、带格式文本、小图片、6000×4000 图片、极长图、文件及文件夹。清理/保留策略测试请使用可丢弃历史或专用 Windows 测试账户。

数据库升级移除未使用的 FTS 派生索引，保留历史、收藏、分组、备注与设置。升级后直接运行旧程序不受支持；回退必须先退出程序，保留升级后的完整数据目录，再恢复升级前完整备份。恢复会丢失备份之后新增的数据，不要混用新旧数据库与图片目录。

### 分组验收范围

当前前端只有“历史 / 收藏”视图及类型筛选，没有自定义分组筛选或“移动分组”入口。因此不要求在 UI 中执行这两个不存在的操作，也不将其标为测试通过。本清单中的分组仅指旧数据库 `groups` / `item_groups` 的兼容与引用完整性：使用含分组关联的可丢弃数据，在升级、清理后检查保留项的关联仍存在、删除项没有悬空关联。按日期展示的列表分段不是自定义分组管理。本次只纠正文档，不新增分组功能或删除兼容表。

> Windows 数据隔离：只覆盖进程的 `APPDATA` 环境变量不足以保证隔离。破坏性测试优先使用专用 Windows 账户，并核对程序实际数据路径。不要在当前真实历史上执行清空或缩短保留期限。

## 稳定性观察（约 10 分钟）

- [ ] 任务管理器记录启动稳定后、连续复制/预览/开关后、静置 2 分钟后的 CPU/内存；同时观察 Recopy 及其 WebView2 子进程，截图留档。
- [ ] 重复 3 轮同样操作，观察是否持续增长且不趋于稳定、空闲持续占用 CPU、输入延迟或卡死。单次峰值不直接判定为泄漏，也不要把 macOS 主进程内存数字当作 Windows 门槛。
- [ ] 测试完成后退出 Recopy，确认相关进程退出；重新启动能够继续使用。
