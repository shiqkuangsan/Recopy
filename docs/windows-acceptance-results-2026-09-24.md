- CSV 记录 CPU 累计秒、工作集、私有内存、响应状态；采样不是三轮相同操作加各两分钟静置的受控实验，也不是任务管理器截图。
- 用户总体接受必测结果；没有补造三轮受控实验的测量值。启动/退出/重启早期已观察，不能替代所有自定义设置的重启检查。

## 数据隔离与恢复

早期保存完整原始数据备份并校验。第一次仅覆盖进程 `APPDATA` 的隔离尝试失败：实际真实目录被迁移写入 WAL，单看主数据库 hash 不足以证明无变化。该轮没有在真实数据上执行保留策略清理。

保留当时目录后，完整恢复原备份；随后使用明确的 disposable 数据目录切换执行合成测试。最终 25 个原文件 hash 全部一致、无 WAL/SHM。这次恢复发生在用户重新启动进行人工测试之前。后续用户新增记录仍属于当前真实数据，不应再次用早期备份覆盖。

三种策略均检查 `integrity_check=ok`、外键无错误、剩余图片与条目集合一致、旧分组引用正确。UI 测试保留了合成条目、备注和最近搜索，剪贴板被测试文本替换；没有为了清理测试痕迹删除真实历史。

## 问题处置

### 1. Windows 原图保存测试断言

- 复现：`cargo +1.94.0 test --manifest-path src-tauri/Cargo.toml --lib --locked clipboard::tests::test_save_original_image -- --exact --nocapture`。
- 基线：`path.contains("images/")` 失败，exit 101；之前文件存在和后缀断言通过，不是已证实的存储失败。
- 修复：用 `Path::starts_with(temp_dir.join("images"))` 和 `Path::extension` 验证路径；额外验证文件字节一致。每次使用 UUID 临时目录，避免并发测试冲突及预先删除其他测试目录。
- 不改生产存储函数、不改 schema、不改公开接口。该路径断言按原生组件比较，不硬编码 `/` 或 `\\`。
- 修复后最小测试通过；回滚独立副本后原断言再次失败且源码 hash 与基线一致。完整回归结果见下节。

### 2. 分组文档与当前 UI 不符

`ViewTabs.tsx` 仅 history/pins，`ItemContextMenu.tsx` 没有分组移动操作。清单移除自定义分组 UI 操作要求，解释日期分段与自定义分组的区别。`groups` / `item_groups` 兼容与引用检查仍保留；不是通过删除数据契约掩盖失败。

### 3. 补齐记录与纠正证据归属

本报告补录此前未落盘的清空设置、备注/收藏、快捷键、最近搜索、方向键、20 次图片切换和进程树采样。完整保留失败、受阻、人工总体反馈及跳过项；没有把用户“都算通过”转换为自动化全覆盖。

### 未确认观察（没有运行时修复）

- 预览截图出现背景透出、文本对比度低，重复截图可见；未排除捕获透明窗口造成的现象。没有单项肉眼复核反馈，不宣称已消失。
- 一次大图读取曾报访问拒绝，随后成功采集；一次新文本首次未观察到，明确选中并重复制后出现。均未定位为稳定可复现产品缺陷。
- Windows Rust 构建有既存未使用项/函数指针转换警告；本次不扩展为平台代码重构。
